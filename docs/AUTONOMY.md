# 自主活动什么时候发生

一句话：**没有固定的推送时刻**。后台每 60 秒看一次表，到点了才活动；
下一次的点由上一轮结束时的规划器给出（30–240 分钟之间带 ±10% 抖动），
一天最多 `daily_rounds` 轮（默认 10，自动与手动共用）。

| 项 | 值 |
|---|---|
| 后台自主活动开关 | **关**（`auto=false`）→ 即使到了时间也不会动 |
| 记录里的下次唤醒 | `2026-10-25T18:58:32+08:00`（已过期，但开关关着所以不会补跑；一旦 `/刷站 开启`，下一次 tick 就会立刻跑一轮） |
| 上一轮规划 | `source=search`、`query=历史科普`、`rest_minutes=166` |
| 点赞 | 开（`likes_enabled=true`） |
| 今日已用 | 6 轮（上限 8）、点赞占额 4（上限 3，验收那一次用的是临时上限 4） |

| 1 | 10-24 23:33 | 手动 | ok |

间隔是 33 分、12 分、1 小时 12 分、1 小时 56 分、1 小时 32 分 —— 这就是「30–240 分钟抖动」的真实样子，不是整点、也不是每 15 分钟。

## 2. 机制：什么时候算「到点」

```
每 60 秒 tick 一次
  ├─ 清理过期帧文件（每小时最多一次）
  ├─ enabled=false 或 auto=false → 直接返回（不动）
  ├─ 今日轮次已到 daily_rounds（默认 10，硬上限 16）→ 直接返回
  ├─ 没有 next_wake → 写一个「45 分钟后」的初醒点，返回
  ├─ 现在 < next_wake → 返回
  └─ 到点 → 跑一轮（最长 240 秒），跑完写下一个 next_wake
```

- 下一个点怎么算：`next_wake = 现在 + rest_minutes × random(0.9, 1.1)`，`rest_minutes` 由规划器给，夹在 30–240 分钟；
  规划器失败时退化到 75–180 分钟。
- 一轮里的动作顺序（决定「画面不能买动作」）：先按字幕/元数据筛 → 读最多 `videos_per_round` 条（默认 3）→
  点赞/分享**先把决定做完并记账** → 之后才由 `observer` 记下「本来会看哪一条」→ 最后一轮最多升级 1 条去真抽帧。
- 一轮超时 240 秒；出错时这一轮记 `error`，**先退避 30 分钟再试**——一次瞬时错误（人格还没加载、网络抖一下）
  不会停掉一整天。连续 3 次失败才把 `auto` 关掉，并把最后一次的异常类型与原文记进库里：
  `/刷站 状态` 末行显示「最近一次自主活动失败：HH:MM RuntimeError: …」。日志里只打异常类型，不打印原文。

## 3. 静默时段只拦「分享」，不拦「浏览和点赞」

- `quiet_start=23`、`quiet_end=9`：这段时间她照样可以逛、可以点赞，**只是不往 QQ 发**；
  在静默里想分享的东西会存成待发（`suggestions`），到 09:00 之后由下一次 tick 补发。
- 分享还要过冷却：`share_cooldown_minutes=120`（最少 30）——距上次分享不足 120 分钟就不发，攒成待发。
- 每日分享上限 `daily_shares=5`（硬上限 5），而且**按全天摊开**：09:00 起每小时解锁一条，
  09 点 1 条、12 点 2 条、15 点 3 条、18 点 4 条、21 点 5 条（`share_allowance`）。所以早上不会一口气把
  五条发完，晚上还有额度；`/刷站 状态` 会显示「分享 X/5 条（此刻按全天节奏已解锁 N 条）」。
- 轮次也摊开：每轮结束后按「剩余轮次 ÷ 剩下的可说话时间」算间隔（`spread_rest`，30–240 分钟），
  并且**不会把下一轮排在 23:00–09:00**（`align_to_window`）——夜里跑一轮是浪费额度，
  因为那一轮发不出分享。十轮大致落在 09:00 / 10:24 / 11:48 / 13:12 / 14:36 / 16:00 / 17:24 / 18:48 / 20:12 / 21:36。
- 每日点赞上限 `daily_likes=3`（硬上限 10，含结果不明确的占额）。
- 手动 `/刷站 刷` 不受静默限制（你自己点的），但同样占每日轮次与分享额度。

## 4. 「今天什么都没发生」的六种原因，按顺序查

| 可能 | 怎么确认 | 怎么修 |
|---|---|---|
| 后台没开 | `/刷站 状态` 第一行「自主活动：关」 | `/刷站 开启` |
| 今日轮次用完了 | 状态里「今日浏览轮次 10/10」 | 明天自动归零，或临时调大 `daily_rounds`（≤16） |
| 还没到点 | 状态末行「下次唤醒参考：…」 | 等，或 `/刷站 刷` 手动一轮 |
| 连续 3 次异常把开关关了 | `/刷站 状态` 末行「最近一次自主活动失败：…」；日志 `连续 3 次失败，自主活动已暂停` | 修好原因后 `/刷站 开启` |
| 凭证失效 / B站风控 | 日志里 `risk_control`、`login_required` | 重新扫码 `tools/bili_login.py` |
| 没到「值得分享」的程度 | `videos` 表读到正文但都没到分享标准 | 正常行为：没有值得的内容就不发 |

查日志：`docker logs astrbot | grep feiyu-bili`，每轮会打一行
`[feiyu-bili] 自主活动 status=… read=… liked=… sent=…`。

## 5. 审计入口（都在 `browse.db`，不需要读代码）

- `rounds`：每轮的开始时间、是否自动、结果。
- `videos`：读过哪些、`source` 是 `subtitle`（读到正文）还是 `metadata_only`（只读了标题简介）、`interested`。
- `likes`：每次点赞尝试与结果（`liked`/`uncertain`）。
- `deliveries` / `suggestions`：分享投递与待发。
- `vision_shadow`：后台筛下的「本来会看哪一条」和原因（`vision_off`/`decoder_missing`/`no_text`/`not_interested`）。
- `/刷站 任务` 是这些表的人话版工作台：画面任务、筛选决定、今日用量、转写次数。

## 6. 别和「主动消息」搞混

两个插件都会「自己开口」，但机制完全不同：

| | B站插件（本文件） | 陪伴插件 `astrbot_plugin_feiyu_companion` |
|---|---|---|
| 什么时候 | 30–240 分钟抖动，且到点还要看有没有值得的内容 | 每 60 秒看一次；说完或你说话后掷骰子：白天 5–45 分钟、傍晚 10–90、深夜 30–180 |
| 发什么 | 只有「值得给你看的一条视频 + 一句分享话」才会发 | 主动聊一句日常 |
| 免打扰 | 23:00–09:00 只不发分享 | 23:00–07:00 一条不发 |
| 上限 | 每日分享 5 条（按全天摊开解锁）、间隔 ≥120 分钟 | 每日 30 条、连续 4 条没回就忍住 |

所以「她今天没在 B站 说话」是正常的：B站 那条线默认只在真有东西想给你看时才开口，
而且现在 `auto=false`，连逛都没在逛。

## 7. 想让它更规律/更安静

| 想做的事 | 改哪里 |
|---|---|
| 更频繁地逛 | 调小规划器给出的 `rest_minutes` 不可直接配，只能调大 `daily_rounds`（上限 16） |
| 更少打扰 | 调小 `daily_shares`、调大 `share_cooldown_minutes` |
| 想让它更早开始/更晚结束 | 调 `quiet_start`/`quiet_end`（可说话窗口决定分享额度怎么摊开） |
| 完全静音分享、只逛只点赞 | `daily_shares=0` |
| 只在白天活动 | 把 `quiet_start`/`quiet_end` 拉宽（注意：静默只拦分享，不拦浏览） |
| 暂停一切后台活动 | `/刷站 关闭`（会取消在途任务），或 `enabled=false` |
